# 0008 — CV delivery is a committed static PDF in v1

- **Status:** Accepted
- **Date:** 2026-09-07
- **Deciders:** Roman (second clarify pass, 2026-09-07)

## Context

The second clarify pass cut this feature's scope to the above-the-fold scan only and
re-sized it M → S (spec §3, commit `2394843`). Building `cv.astro` to faithfully reproduce
the locked `cv-template-reference.pdf` layout is non-trivial CSS work (ADR-0004's own
"Negative") and is roadmap **step 4** — a later feature, after this page (step 3). The
landing page still has to ship a working **Download CV** control at launch. This ADR
records the decision, made with the user during that pass, to serve a hand-committed PDF
for v1 and defer build-time generation. It is a scoped, temporary exception to the
Accepted foundational **ADR-0004**, not a reversal of the "site is the single source of
truth" intent.

## Decision drivers

- Spec §3 scope (post-clarify): v1 is the above-the-fold scan; the CV **print route build**
  is explicitly out of this feature and lives in roadmap step 4.
- SAD §11 risk: a Download-CV control with no file behind it must never ship — a missing
  or dead link fails a launch AC.
- Effort budget ~1 week, solo; roadmap already sequences CV generation as a separate step
  after this page.
- Standing goal unchanged: the page and the CV must not drift (CONTEXT.md invariant,
  idea-brief §6) — this decision keeps that as the target and treats the gap as accepted
  debt with a manual check.

## Considered options

1. **Commit a hand-maintained CV PDF under `site/public/` for v1; defer ADR-0004's
   build-time `/cv` generation to roadmap step 4.** The Download-CV control links to the
   committed file.
2. **Pull ADR-0004 forward into v1 scope** — build `cv.astro` to the locked template now
   and keep the Playwright/Chromium `postbuild` step.
3. **Block the launch until step 4** — ship the page with the Download-CV control disabled
   or absent until CV generation exists.
4. **Point the control at an externally hosted copy** (LinkedIn export / a file host) — no
   committed asset and no generation.

## Decision outcome

**Chosen:** Option 1. It ships a working, correctly-named CV download on day one, inside
the S-sized scope and the effort budget, without dragging the full `cv.astro` template
build into an above-the-fold-only feature. Option 2 re-expands exactly the scope the
clarify pass deliberately cut. Option 3 ships a landing page with no CV — it fails a
launch AC. Option 4 moves drift outside Roman's control and makes the download depend on a
third party's URL and hosting staying stable.

## Consequences

**Positive**
- The landing page ships with a working, meaningfully-named CV download within the S scope.
- No Chromium/Playwright on the `site` CI + deploy path for v1 — the `npx playwright
  install --with-deps chromium` steps and the `postbuild` PDF generation come out, so both
  jobs get faster and smaller.
- `site/src/pages/cv.astro` and `site/scripts/generate-pdf.mjs` stay in the tree, unwired —
  roadmap step 4 re-enables them rather than rebuilding from scratch.

**Negative**
- The committed PDF can drift from the Profile content and the live page — the precise risk
  ADR-0004 exists to remove. Mitigated only by a **manual** release-parity check (surname,
  headline, employment dates) before each launch and after each content edit (spec §8);
  that check is itself accepted debt and easy to forget.
- A binary artifact is now tracked in git and must be regenerated by hand from the "Classic"
  CV source whenever the CV content changes.
- ADR-0004 is partially contradicted for the lifetime of v1 — a reader has to hold both
  ADRs together to know the current state.
- `CLAUDE.md`'s `## site` section changes ("CV PDF is generated, never committed" → "CV PDF
  is committed") and will revert at step 4.

**Neutral**
- Reversible by design: roadmap step 4 deletes the committed PDF, restores the `postbuild`
  step and the CI Chromium install, and this ADR flips to `Superseded by` ADR-0004's
  resumption at that point.
- The `profile` content-collection schema — shaped by the CV template per ADR-0004 — is
  unaffected; no schema change rides on this decision.
- No impact on the tracker or on the existence of the `/cv` web route; `cv.astro` remains a
  viewable page.
